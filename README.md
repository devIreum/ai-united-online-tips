# AI United - Онлайн-чаевые

Прототип сервиса онлайн-чаевых для кейс-чемпионата «В ПОТОКЕ» (кейс 3).

Система моделирует прием чаевых по QR-ссылке, расчет комиссии, обработку платежных ошибок и распределение чаевых между сотрудниками. Прототип работает с тестовыми данными и эмулятором платежного шлюза.

## Технологии

- C++17 - бизнес-логика и сценарии тестирования
- SQLite3 - хранение данных о платежах и аудит
- OpenSSL - HMAC-SHA256 и хеширование
- CMake - сборка проекта

## Возможности

- Выпуск QR-ссылки с HMAC-подписью, привязкой к заведению и сотруднику.
- Проверка подписи и срока действия ссылки.
- Прием тестового платежа на сумму от 50 до 10 000 рублей.
- Расчет комиссии 5% в целых копейках.
- Защита от повторного списания через `Idempotency-Key`.
- Обработка успеха, отказа банка и неопределенного результата платежа.
- Сверка платежей со статусом `PENDING_UNKNOWN`.
- Разделение прав доступа по ролям (RBAC).
- Хранение маски номера карты вместо полного PAN и хеша телефона с солью.
- Журнал аудита с проверкой целостности цепочки записей.
- Распределение общего пула чаевых пропорционально рабочим часам.

## Сборка и запуск

CMake задает общую схему сборки для разных ОС. Команды `cmake -S . -B build` и `cmake --build build` одинаковые, но компилятор, пути к OpenSSL и SQLite3 и установка библиотек зависят от системы. Текущая реализация использует расширение `__int128` компиляторов GCC/Clang и не проверялась с MSVC.

### macOS

Понадобятся инструменты разработчика Xcode Command Line Tools, CMake, OpenSSL и SQLite3. При наличии Homebrew:

```bash
xcode-select --install
brew install cmake openssl@3 sqlite
cmake -S . -B build -DOPENSSL_ROOT_DIR="$(brew --prefix openssl@3)"
cmake --build build
./build/tips_tests
./build/tips_demo
```

Если инструменты Xcode уже установлены, команду `xcode-select --install` выполнять не нужно.

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install -y g++ cmake libssl-dev libsqlite3-dev
cmake -S . -B build
cmake --build build
./build/tips_tests
./build/tips_demo
```

Для запуска тестов через CTest:

```bash
ctest --test-dir build --output-on-failure
```

## Тестирование

Реализованы 12 автоматизированных проверок: пять основных сценариев (успех, отказ, неверные данные, повторный запрос, таймаут) и дополнительные проверки RBAC, статусов, комиссии, распределения пула, целостности аудита, отсутствия полного номера карты в БД и нового сценария оплаты в общий пул смены.

Результат контрольного прогона: `12 passed, 0 failed` (см. `materials/test_output_cpp.txt`). Для воспроизведения результата запустите `./build/tips_tests` в своей среде.

Тестовые номера карт эмулятора:

| Номер | Результат |
| --- | --- |
| `4242424242424242` | Успешная оплата |
| `4000000000000002` | Отказ банка |
| `4000000000000119` | Таймаут ответа, последующая сверка |

## Ограничения

Это учебный прототип, а не готовая платежная система. Реальные банковские операции, HTTP API, вывод денег, учет налогов и производственная инфраструктура не реализованы. QR-домен `tips.example` используется как пример. Тестовые номера карт не предназначены для настоящих оплат.

В текущем прототипе база данных хранится в памяти, ключ QR демонстрационный, а фактическая нагрузочная производительность не измерялась. Для реальной эксплуатации потребуются внешний эквайер с токенизацией, безопасное управление ключами, надежное постоянное хранилище, мониторинг и дополнительные проверки безопасности.
