# AI United - Онлайн-чаевые (кейс 3)

Учебный консольный прототип платежного сервиса для кейс-чемпионата «В ПОТОКЕ».

**Стек:** C++17, SQLite3, OpenSSL (Crypto), CMake. Настоящие деньги не переводятся. В приложении отсутствуют банковская интеграция и HTTP-сервер.

## Что умеет

- Менеджер выпускает QR-ссылку сотрудника с подписью HMAC-SHA256 и сроком действия.
- Гость задает сумму 50-10 000 руб. и оплачивает тестовой картой.
- Сервис считает комиссию 5% в целых копейках, не используя `float`.
- Один `Idempotency-Key` не может вызвать повторное списание.
- Неопределенная оплата получает `PENDING_UNKNOWN`, затем уточняется с помощью `reconcile()`.
- База SQLite хранит маску PAN вместо полного номера карты; телефон хранится как хеш с солью.
- Журнал аудита позволяет обнаружить изменение старой записи.
- Пул смены делится по числу часов без потери копеек.

## Запуск на Linux (Ubuntu / Debian)

Откройте терминал в папке с `CMakeLists.txt`:

```bash
sudo apt update
sudo apt install -y g++ cmake libssl-dev libsqlite3-dev
cmake -S . -B build
cmake --build build
./build/tips_tests
./build/tips_demo
```

Можно также запустить `ctest --test-dir build --output-on-failure`.

**Ожидаемый результат тестов:** `RESULT: 11 passed, 0 failed`. Команда `ctest` пишет `1/1`, потому что запускает один файл `tips_tests`, а тот проверяет 11 отдельных случаев.

На Windows проще всего использовать WSL Ubuntu (с теми же командами). Вариант сборки с MSVC потребует заменить применение `__int128` в расчете пула на переносимую реализацию. На macOS нужен компилятор C++17 и установленные зависимости SQLite3, OpenSSL, CMake; путь OpenSSL может потребовать настройки CMake.

## Проверяемые тестовые карты

| Карта | Результат эмулятора |
| --- | --- |
| `4242424242424242` | Успех |
| `4000000000000002` | Отказ банка |
| `4000000000000119` | Платеж проведен, ответ не дошел: `PENDING_UNKNOWN` |

**Не используйте настоящие карты.** Адрес `https://tips.example/t` только демонстрационный. Для настоящего продукта нужна платежная форма эквайрера, которая передает токен, а не полный PAN.

## Основные идеи, которые нужно понимать на защите

1. `HMAC` - криптографическая подпись URL, чтобы не подменили сотрудника или заведение.
2. `Idempotency-Key` - UUID платежа; тот же запрос возвращает прежний результат, другой запрос с тем же UUID вызывает ошибку.
3. `PENDING_UNKNOWN` - банк мог списать деньги и потерять ответ; повторять оплату нельзя, требуется сверка.
4. `CREATED -> PENDING -> SUCCEEDED/DECLINED/PENDING_UNKNOWN` - разрешенные изменения статуса.
5. `amount_kop` - целое число копеек; комиссия вычисляется через целочисленное деление.
6. `audit` - каждая запись содержит хеш предыдущей; скрытое изменение обнаруживается проверкой цепочки.

## Границы безопасности

Это **учебный прототип** с демо-ключом и SQLite в памяти, без TLS/HTTP, реальных выплат, нагрузочного тестирования, полноценной системы аккаунтов и фона по расписанию. Трехсекундный таймаут и p95 менее 500 мс остаются требованиями, а не измеренными результатами. Для промышленной версии необходимы банковская песочница, токенизация, управление секретами, защита от гонок и операционный мониторинг.
